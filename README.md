# 邮史展品

青槐邮史室整理小型借展的邮封文字。实物身份、邮局、邮路及历史日期为虚构。

本项目在 `data/records.json` 的合成资料上提供一套可反复运行的编目、邮路核订
与展稿核证工具：抄录释读结构化到具体戳迹，枚举所有仍可成立的递送解释，
只把交集作为已核实内容，并按柜中实际封件生成展签、追踪换展导致的说法变化。

## 资料格式

数据位于 `data/records.json`，以 UTF-8 保存。各表的记录以本表内的 `id` 或 `seq` 识别。原话保留提交时的文字。

每件封有自己独立的 front、back、insert 分面。marks 的 order_hint 为馆员按叠印推得的可见先后，空值代表未辨清。readings 的 mark 是同一物理戳迹，原文保留各抄录的争议。开放时段含首尾日期。routes.min_hours 为通达下界，通路标示普通件或退件。时代对照采用馆内已核准的合成年表。

- `covers` 保存封件与展签现用名称。 字段为 `id`、`image`、`insert`、`note`。
- `offices` 保存邮局、历史简称和局址有效期。 字段为 `id`、`name`、`aliases`、`open`、`close`。
- `era` 保存馆内年代对照与封件启用信息。 字段为 `id`、`text`。
- `routes` 保存开放通路和最短通达时间。 字段为 `id`、`origin`、`destination`、`min_hours`、`direction`、`open`、`close`。
- `marks` 保存同一邮封各面上的戳迹及可见的大致次序。 字段为 `id`、`cover`、`side`、`order_hint`。
- `readings` 保存多位抄录人的原始释读。 字段为 `id`、`mark`、`reader`、`text`、`certainty`。
- `display` 保存馆方借展组合及说明草稿。 字段为 `id`、`covers`、`time`、`draft`。

## 核订规则（工具如何取舍证据）

1. **同一印痕的多份释读不投票。** 每位抄录的说法带来源保留；某一位数字
   只有在所有可行解释中都相同才可确认，票数不会把存疑数字升格为定论。
2. **标记只落到其所在戳迹。** “后补盖/纪念补盖”“退回”“所称寄地/疑是始发”
   “后人释注”“叠盖候选”“墨色方向异”等短语解释到具体 mark，不是全封结论。
   明确为纪念补盖或后人释注的痕迹保留作物件说明，但排除其递送证据资格。
3. **历史简称按年代定局。** 同一简称在不同时期可属不同邮局（如“河湾”在
   1961-07-01 前后分属北河湾局 P1 与南河湾局 P2），解析必须结合事件日期与
   邮局开闭窗口；年份未定时保留全部候选，不替残字猜补。
4. **日期保留范围与来源。** 年号纪年（壬17→1961）、只写月日、公元年、
   “疑为1962”这类推测、括号里的后人释读分别标注；馆内记时用当地零时，
   跨日边界由日期加时刻的普通时间差处理。
5. **封背第二戳不自动等于第二次投递。** 趟次按路网中的退件段切分，
   同一天的两个戳不强制同趟；实际邮路允许一次退回（至多一段连续退件路程）
   与再次寄出。
6. **可行解释必须同时满足：** 戳迹读法可成立、邮局当日开放、相邻戳迹间在
   开放路网上走得通（允许经过未留戳中转局）、累计最短通达时间不超过时间窗、
   全程至多一次退回。无年份戳迹还须落在同封明写年份锚点的合理时间窗内，
   不得借“只写月日”跨年漂移。
7. **确认只取交集。** 仅在所有可行解释中都相同的站/路段给“已核实”；
   其余分支指出复查哪处原字会改变路线或“首日实寄”归类，不挑一条行程消矛盾。
   没有任何解释成立时如实报矛盾。
8. **通达时间护栏。** 分属退回前后不同趟次的两个戳，其日期差不得作为普通
   通达时间（不能拿第一次的起日配第二次的到日）。
9. **展签按柜中实物分层。** 已核实递送、题签说法、未知段与实物说明分述；
   换入同图另一件后按新封自己的证据重新裁决。两件共同解释一种邮路时，
   必须两件都支持且年代相容，否则互证不成立。

## 命令行用法

工具仅使用 Python 3.11 标准库。仓库根目录提供启动器，推荐以隔离模式运行，
避免从当前目录意外载入第三方模块：

```sh
# 结构化编目：年号换算、局名称谓、把握程度、戳迹标记
python3 -I posthist_cli.py catalog

# 核订单件或全部封件的可行递送解释（--json 输出机器可读结果）
python3 -I posthist_cli.py verify --cover K1
python3 -I posthist_cli.py verify --json

# 核证展陈草稿（逐件、逐说法，含年代不相容与互证裁决）
python3 -I posthist_cli.py exhibit

# 生成单件封的扫码展签稿（已核实/题签说法/未知段/实物说明）
python3 -I posthist_cli.py label --cover K1

# 换展分析：逐说法比较前后状态，点名涉及的封、释读与年代限制
python3 -I posthist_cli.py swap --display D2 --out K1 --into K2
```

所有子命令支持 `--data 路径/records.json` 指向其他合成资料，并支持 `--json`。

## 代码结构

```
posthist/
  models.py   资料记录的数据类
  dates.py    年号/月日/残字/括号释读解析、馆内年表、时间窗口
  parse.py    抄录释读解析为带证据来源的戳迹事实（不投票）
  catalog.py  资料装载、引用校验、历史简称按年代解析
  engine.py   枚举全部可行递送解释、交集确认、退回/首日/通达护栏
  exhibit.py  展陈核证、同图换件差异、展签稿
  cli.py      命令行入口与 JSON 序列化
tests/        unittest 测试（含合成内存资料的规则级用例）
posthist_cli.py   隔离模式启动器
run_tests.py      隔离模式测试启动器
```

## 查看资料与自检

```sh
python3 -m json.tool data/records.json
python3 -I run_tests.py          # 隔离模式运行全部 42 个测试
python3 -m unittest discover -s tests -v   # 常规模式亦可
```
